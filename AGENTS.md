# AGENTS.md

This file provides guidance to coding agents (Claude Code, Cursor, Codex, Copilot, etc.) working with this repository. Human contributors: read [`CONTRIBUTING.md`](./CONTRIBUTING.md) first.

## Tech Stack

| Layer | Choice |
|-------|--------|
| Framework | **Nuxt 4** (Vue 3 + Nitro engine) |
| UI | **shadcn-vue** (new-york style) + **Tailwind CSS v4** + **Lucide icons** |
| State | **Pinia** |
| SEO | **@nuxtjs/seo** |
| Auth | **better-auth** (email/password + Google OAuth + GitHub OAuth + admin plugin) |
| Database | **PostgreSQL** (Drizzle ORM, postgres-js driver) |
| Deployment | CF Workers / Vercel / Docker (Nitro preset switching) |
| Package Manager | **pnpm** |

## Development

```bash
pnpm install                    # Install deps (postinstall runs nuxt prepare)
pnpm dev                        # Dev server at http://localhost:3000
pnpm build                      # Production build
pnpm preview                    # Preview production build

# Database (requires DATABASE_URL env var)
pnpm generate:migration         # Generate Drizzle migration after schema changes
pnpm migrate                    # Run database migrations

# Cloudflare Workers deployment
pnpm build:cf                   # Build with NITRO_PRESET=cloudflare-module
pnpm deploy:cf                  # Deploy .output to CF Workers via wrangler

# UI components
pnpm dlx shadcn-vue@latest add <component>  # Add shadcn-vue component (run pnpm install first to ensure .nuxt exists)
```

## Architecture

### Frontend (`app/`)

- `pages/` — File-based routing: home, login, post detail (`p/[slug]`), roadmap, admin dashboard (`dashboard/*`)
- `layouts/` — `default` (public pages) and `dashboard` (admin)
- `components/ui/` — shadcn-vue base components (no prefix, `pathPrefix: false`)
- `composables/` — `useApiFetch` (request wrapper), `useAuth` (auth state), `usePermission` (permissions)
- `stores/` — Pinia stores: `board`, `postDetail`
- `lib/md-editor-helper.ts` — Workaround for md-editor-v3 nested in shadcn Dialog (prevents internal popups from closing the outer Dialog); read this first when hitting similar issues

### Backend (`server/`)

API routes follow Nuxt file-based routing (`server/api/`), organized by resource:

- `auth/[...all].ts` — better-auth catch-all handler
- `boards/` — Public board list
- `posts/` — Post CRUD + voting
- `posts/[postId]/comments/` — Comment CRUD
- `comments/[id]/` — Comment edit, delete, like
- `admin/` — Admin APIs (boards CRUD + reorder, posts management), requires admin role
- `seed.post.ts` — Seed data endpoint

Server utilities (`server/utils/`, auto-imported by Nitro):
- `auth.ts` — `getUserSession()`, `requireAuth()`, `requireAdmin()` (three-level auth helpers)
- `db.ts` — `useDB()` returns Drizzle instance
- `slug.ts` — Slug generation

### Database

- **Connection**: `server/db/index.ts`, using `postgres` driver + `drizzle-orm/postgres-js`
- **Schema**: `server/db/schemas/index.ts` as entry point, defines board, post, comment, commentLike, vote tables and all relations
- **Auth Schema**: `server/db/schemas/auth.ts` (generated by better-auth) + `auth-schema.ts` (root-level reference copy), defines user, session, account, verification tables
- **Migrations**: `server/db/migrations/`, managed via `drizzle-kit generate` and `drizzle-kit migrate`
- **Drizzle Config**: `drizzle.config.ts`, schema path is `./server/db/schemas/index.ts`
- **ID Strategy**: Business tables use UUIDv7 (time-ordered), auth tables use text IDs
- **v0.2 additions**: `pgvector` extension + similar-merge tables (`post_embedding`, `duplicate_group`, `duplicate_member`, `duplicate_suggestion`) in `server/db/schemas/index.ts`; embeddings use OpenAI `text-embedding-3-large` at 768d

### Auth

- **Server**: `server/utils/better-auth.ts` — better-auth instance with Drizzle adapter + email/password + Google OAuth + GitHub OAuth + admin plugin
- **Client**: `app/lib/auth-client.ts` — `createAuthClient()` with `adminClient()` plugin
- **API Route**: `server/api/auth/[...all].ts` — catch-all route proxying to better-auth

### Shared Code (`shared/`)

Nuxt 4 `shared/` directory (importable from both frontend and backend):
- `schemas/` — Zod validation schemas (board, post)
- `types/` — TypeScript type definitions (board, comment, pagination, post)

## Code Conventions

- TypeScript throughout
- Add shadcn-vue components via CLI, not manually
- Run `pnpm install` before adding components (`.nuxt` directory must exist for path alias resolution)
- `~~/` alias points to project root (for server-side imports like `~~/server/db`, `~~/lib/auth`)
- `@/` or `~/` alias points to `app/` directory (for frontend imports)

## Upstream Sync (feedlog fork)

This repo (`imoyao/ddb-feedback`) is a **fork of `linkcraftstudio/feedlog`** with custom DDDB-feedback modifications. We keep our customizations while periodically pulling upstream updates.

- The job lives at `.github/workflows/sync-upstream.yml` (NOT in the `fundmate` repo). It runs on a weekly schedule and can be triggered manually via `workflow_dispatch`.
- It fetches `upstream/main` and performs a plain `git merge upstream/main --no-edit`, then pushes to `origin/main`.

**Hard constraints for any AI/agent editing this workflow:**

- **Never use `--strategy-option theirs`** (a.k.a. `-X theirs`). That flag silently overwrites local DDDB customizations with upstream content on conflict, defeating the whole point of keeping our fork customizations. Conflicts must be surfaced, not auto-resolved in upstream's favor.
- On merge conflict, the workflow must **abort the merge and open an Issue** listing the conflicting files (`steps.merge.outputs.conflict_files`), leaving resolution to a human. It must never auto-commit a conflict resolution.
- **No dead-code options.** Do not add a `rebase` choice (or any strategy not actually implemented) to `workflow_dispatch`; a previous version had an unimplemented `rebase` branch that falsely reported success.
- Capture the conflict file list **before** `git merge --abort`, since the abort clears conflict markers and `git diff --diff-filter=U` would then return empty.
- Use a stable `actions/checkout` version (currently `@v4`), not an unreleased major (e.g. `@v5`).
